# 3080 20G + 8G KV 配方（Linux 实测）

一台 RTX 3080 20G 上跑 Qwen3.8-27B-Coder390（Q3LynnStyle16G-MTP，dense，qwen3_5 后端）
的启动参数与读数。**只是一份参考，不是最优解。**

---

## 环境

| 项 | 值 |
|---|---|
| GPU | RTX 3080 20 GiB（sm_86） |
| 驱动 | 580.142 |
| CUDA runtime | 13.3（小版本兼容跑在 R580 驱动上） |
| 内存 | 30 GiB |
| 系统 | Ubuntu 24.04 |

## 模型

```
Qwen3.8-27B-Coder390-Q3LynnStyle16G-MTP.ninfer
架构：Qwen3_5ForConditionalGeneration / model_type: qwen3_5
```

**注意**：这是 **dense** 模型，走 `qwen3_5` 后端。
`Qwen3.8-Flash-Next` 是**另一个模型**（`Qwen4ExpForConditionalGeneration`，MoE），
走 `qwen3_8_flash_next` 后端——名字里的 "3.8" 容易误导。

## 启动

```sh
./ninfer-serve /models/Qwen3.8-27B-Coder390-Q3LynnStyle16G-MTP.ninfer \
  --port 8089 --host 0.0.0.0 \
  --max-context 32768
```

## 显存账

```
20 GiB 总计
 - 12.1 GiB  权重
 -  3.29 GiB runtime
 -  3.90 GiB 剩余
 = 19.29 GiB
```

**余量 3.90 GiB**：如果要用 `--spec mtp` 投机解码，或者开 `--vision`，这点余量不一定够，
需要实测。

## 校准会落盘

第一次启动 39.9 s 做路由校准，之后同机会命中 `device profile ...(calibration)` 不再重测。

## 关于 `--parallel 2`

官方文档的 `--parallel 2` 已经是实测最优。加并发对 `small_t_i8` 那一段**零收益**，
只会多吃内存。详见 [gotchas #5](gotchas.md)。
